# 实物切割票 v1

车间提供 stock 的唯一 id、material、length_mm、trim_head_mm、trim_tail_mm，以及 orders 的唯一 id、material、piece_mm、quantity。数量与毫米均严格整数，单次最多1000根原材/1000条订单/10000件。kerf_mm 为每一件后必切掉的锯缝（可0）；min_offcut_mm 定义可回收余材最小长度。头尾修边由调用者给定，必须留出正可用长度。

按 piece_mm 降序、order_id 升序、unit(1起)升序逐件处理；同材候选中选切后余长最少者，按 stock_id 打破平局。分配不改变材种，找不到候选的件记录为unfilled，不悄悄借用其他材或缩短件。不是全局最优算法，启发式有可能报告未满足而存在其他可行组合。

切割坐标从原材头部0起，以半开[start,end)表示成品，再占用[end,kerf_end)锯缝；尾端保留trim_tail。最后锯缝之后至尾修边之前为余料。每根原材遵守：总长=头尾修边+成品总长+锯缝总长+余料。只为实际使用原材出工单；unused_stock_ids原封保留。有效输入即使不齐套也退出0，summary.complete和unfilled明确表达缺件；非法输入/目标已存在退出2。先全部算完，再原子新建报告，不覆盖旧工单。

基线不接机床、不维护库存余额，不处理木纹、疤结、拼接、二维板材或跨日余材回收；可回收余材只是实测切后清单，不自动当下一批新原材。

# 跨批次库存工作区 v1

`stock-workspace` 在单批契约之上维护跨批次库存。工作区是一个目录：`state.json` 保存全部状态（库存条目、已提交批次、修订版），`lock` 文件用于提交串行化。状态更新先写临时文件再原子替换，崩溃后只会看到旧版或新版，不会有半次扣料或半份余料。

初始原材沿用 stock 行契约。批次输入沿用 orders、kerf_mm、min_offcut_mm 规则，另需非空且稳定的 job_id。计划与切割沿用单批的确定性分配、毫米坐标、缺件与余料口径。

库存条目：每段库存有工作区内唯一且稳定的 entry_id（初始原材 `stock/<id>`，余料 `offcut/<job_id>/<父条目>`），并保留来源工单与原材身份（source、root_stock_id）。初始原材带原头尾修边；余料条目的 length_mm 就是自身可用整段长度，不再套用修边。余料只服务同材订单。仅 `offcut_reusable=true` 的余料入库；锯缝、修边与不可回收废料永不入库。

计划是对指定修订版的预览，不预留、不改变库存；计划记录 base_revision、规范化请求及其哈希。提交时：base_revision 不等于当前修订版报过期；计划内容与当前状态重算结果不一致报无效；job_id 已提交且请求与计划哈希一致时幂等重放原结果，否则报冲突。提交只消耗实际分配到切割票的条目，未使用条目与缺件订单保持可见；每张切割票的可回收余料在同一原子提交中入库，后续计划可用。

提交结果含库存修订版、消耗与新增条目、缺件与切割报告，可经 `status --job` 查询。非法输入、目标已存在、重复或未知库存身份、版本过期、幂等冲突均退出2，已有工作区、提交记录与输出文件保持不变。并发提交同一修订版至多一个成功，其余按过期处理，可重新计划后再提交。

# 质量事件追溯与隔离 v1

质量事件输入 `incident_id`（非空）与 `stock_ids`（一个或多个唯一初始原材 id，兼容单值 `stock_id`）。事件作用于这些根原材，以及由它们逐批（可多代余料）产生的全部后代库存条目。`roots` 在报告与查询中按字典序稳定排序。

登记 `incident register --workspace W --source S --output O` 生成稳定报告：每个根原材下列出当前及历史全部库存条目（`entries`，含 `status` 与 `active_incidents`）与全部已提交切割票中由该根切出的成品件（`pieces`，含 `job_id`、`entry_id`、`entry_kind`、`order_id`、`unit`、切割坐标 `start_mm`/`end_mm`/`kerf_end_mm`），并按根给出 `summary`（条目数、各状态条目数、件数、涉及批次）。报告顺序仅由 id 与坐标决定，重复登记返回同一结果。

质量事件只标记质量影响，不改写历史：已提交切割记录与 `status --job` 结果保持不变，已消耗条目始终为 `consumed`，解除事件也不会将其恢复为可用。隔离的真实效果在查询与计划时按活动事件即时计算。

状态查询 `status` 将每个可用条目分为 `available`、`consumed` 或 `isolated`（可用但被某活动事件覆盖），并在条目上给出 `active_incidents`，并在顶层给出 `incidents`、`active_incidents` 与 `active_incidents_by_root`。`incident status` 查询全部或单个事件的登记/解除修订版与当前隔离条目；未知事件报错退出2。

任何根原材只要仍有活动事件，其全部可用余料后代都不得进入新计划；`plan` 只使用 `available` 条目，被隔离条目作为缺件留在 `unfilled`。`incident release --incident I` 只关闭 `I`；同一根仍被其他活动事件覆盖则继续隔离。首次登记或解除使可用条目集合变化时推进库存修订版（`registered_revision`/`released_revision` 记录在事件上），使此前生成的计划因 `base_revision` 过期而不能提交；若事件未改变可用集合（例如根已全部消耗）则不推进修订版，`revision_changed=false`。

同一 `incident_id` 以相同根集合重放返回原结果且不改变状态；同 id 不同根集合报冲突；已解除事件不可重新激活。未知原材、重复 id、重复或空根集合、非法输入、已存在且内容不同的输出均以失败结束（退出2），并保留此前事件、库存与输出文件；输出文件在状态持久化前先校验，避免出现状态已改而输出失败。

# 成本登记与连续关账 v1

成本登记 `price register --workspace W --source S --output O` 的输入：`price_id`（非空）、`stock_id`（一个初始原材 id）、`amount_cents`（非负严格整数，该整根原材的全部采购成本，包含以后才会修掉的头尾）、`expected_price_revision`（非负严格整数）。工作区在库存修订版之外独立维护从0开始的成本修订版，每次成功的新登记推进一次并把该根总成本**替换**为新金额（不追加）；期待版本必须等于当前成本版本。相同 `price_id` 相同完整输入的重试返回原结果，且优先于期待版本检查；同 id 不同输入、未知根、非法金额均退出2。登记不推进库存修订版，也不使已有切割计划过期。零价是合法已登记价格；所有根都已登记价格后才能 `cost` 查询或 `close run`，有缺价时错误信息列出缺价根，不以0估价。`price status` 查询当前成本修订版、各根最新价格、缺价根与登记历史。

成本沿库存来源链逐层传递，全程整数运算。未切割的初始原材持有全部采购成本；一张已提交切割票把所消耗条目的整数成本按物理长度分给头修边、每件成品、每道锯缝、余料及尾修边，忽略零长度段。分摊规则：每段先取 `floor(条目成本 × 段长 ÷ 条目总长)`，剩余分币按精确余数从大到小各补1分，余数相同则物理起点更小者优先，不用浮点近似。可回收余料携带此次分得的整数成本进入下一代，下一张票以该成本按同一规则重新分摊；禁止绕过中间取整把根成本直接摊给全部最终成品。不可回收余料（`offcut_scrap`）、头尾修边（`trim_head`/`trim_tail`）与锯缝（`kerf`）归入损耗。每根原材在任意截点满足：成品累计成本＋损耗累计成本＋尚未消耗库存成本＝该根当时采用的采购成本。已消耗的父条目不再作为库存计价；被质量隔离但尚未消耗的条目仍持有库存成本，登记或解除事件不产生价差或耗用。

`cost --workspace W` 按当前库存修订版与各根最新价格返回明细：每件成品以 `(job_id, entry_id, order_id, unit)` 唯一标识；每段损耗以工单、来源条目、类别及半开坐标 `[start_mm, end_mm)` 标识；存量以 `entry_id` 标识。输出含各明细整数分值、根原材身份、每张票的 `input_cents` 与逐段 `segments` 分摊，以及按根、材种和全工作区汇总的守恒结果（`summary.by_root`/`by_material`/`total`，各自 `pieces_cents + loss_cents + inventory_cents = total_cents = price_cents`）。同一根的不同代余料不会重复相加；价格更正沿来源链传递到已消耗余料的后代成品与损耗。

关账 `close run --workspace W --source S --output O` 的输入：`close_id`（非空）、`previous_close_id`（首轮为 null，此后必须是最近一次成功关账的 id）、`expected_inventory_revision`、`expected_price_revision`。成功时冻结这两个截点、当时每根采用的价格、完整成本明细与桥接表；以后的切割、质量事件或改价都不改变该关账的查询结果（`close status [--close ID]`）及原输出。库存截点 R 只包含提交修订版不大于 R 的切割票，按来源链还原当时的存量，不以当前 `status` 代替历史存量；质量事件造成的无切割修订版同样可以成为关账截点。

桥接把变化分成两个可分别核对的部分：先在上一轮库存截点上用本轮价格重算，减去上一轮冻结明细，得到历史价差（`price_change_cents`）；再用同一本轮价格计算本轮库存截点明细，减去刚才的重算，得到本轮生产转移（`production_cents`）。各明细取三个投影的身份并集，缺失金额视为0，每行列出上轮余额 `opening_cents`、历史价差、生产转移与本轮余额 `closing_cents`，负数合法。首轮以“库存截点0、本轮价格下全部初始原材”为期初，历史价差全为0，生产转移为期初至本轮截点之差。每行及按根/材种/整体汇总均满足 期初＋价差＋生产转移＝期末；每根生产转移合计为0，历史价差合计等于该根新旧采购总价差。无切割且无改价也允许关账，变化为0。

同一 `close_id` 相同完整输入的重试返回原冻结结果，即使期待版本已过时或后面已有新关账；同 id 不同输入报冲突。新关账的上一轮身份或任一期待版本过期时失败（退出2），不能覆盖或分叉已有关账链。成本登记、切割提交和关账并发时，关账在提交锁内取到同一个一致截点。关账状态及冻结明细随 `state.json` 一次原子替换持久化；进程在保存或导出时中断后可按原输入重试补出同一结果，不重复记账。输出沿用原子新建：已有相同结果可重放，内容不同则失败并保留旧文件；输出冲突在状态变更之前即被判定，不会先改成本或关账状态。旧工作区的 `state.json` 缺少成本与关账字段时按空成本历史就地升级，无需人工改文件。

# 成品配套交付与质量召回定位 v1

`delivery` 在已提交切割票的真实成品之上做整套配货、出库与交付追溯。工作区在库存修订版、成本修订版之外独立维护从0起的成品修订版（`finished_revision`）：每次新的切割提交、每个质量事件首次登记或首次解除、每次新的交付提交，都在对应事实落盘的同一原子更新中把它推进一次；这些操作的幂等重放不推进。质量事件即使未改变可用库存条目也推进此版本（已切成品可能被隔离），登记第二个覆盖事件、解除其中一个同样按真实事件变化推进。价格登记与关账不推进。旧工作区缺少交付字段时按成品修订版0就地升级，成品事实在读取时从全部既有提交恢复，无需人工改文件。

预览输入 `delivery plan --workspace W --source S --output O`：`dispatch_id`（非空）、`candidate_pieces`（1至32个互不重复的实物引用，各含非空 `job_id`/`entry_id`/`order_id` 与正严格整数 `unit`）、`kits`（1至8个）。每套 `kit_id` 非空且请求内唯一，`priority` 为非负严格整数（数值越小越优先），`slots` 1至4个、全请求不超过24个。槽位含套内唯一非空 `slot_id`、非空 `material`、正严格整数 `min_mm`/`max_mm`（`min_mm` 不大于 `max_mm`）与非空 `grain_group`。字段错误、布尔冒充整数、规模越界均失败（退出2）。输入数组的顺序不携带语义：候选、套件、槽位在规范化请求中分别按引用、`(priority, kit_id)`、`slot_id` 排序，重排输入数组得到完全相同的计划。

只认本工作区已提交切割票中的真实成品：材种、长度（`end_mm-start_mm`）与根原材均从原始切割事实取得；未提交计划里的切件、缺件、余料条目与损耗不能充作成品；不同工单或来源条目上的同名订单件号是不同实物。未知或重复引用失败。已出库或根仍被活动质量事件覆盖的已知件列入 `excluded_pieces`，分别给出占用它的 `delivered_by` 交付身份与 `active_incidents` 活动事件（两者可同时成立），不参与配货；其余候选为可配池。

配货约束：每个槽位用一件同材且长度落在闭区间 `[min_mm, max_mm]` 的成品，不截短、不拼接、不重复使用；同一套内 `grain_group` 相同的槽位必须来自同一根初始原材（多代余料切出的件仍按其根判断），组名在不同套件之间互不关联；套件只能整套选中或整套未配，未选套不占用任何件。配货在全部候选与套件之间求全局唯一最优，依次比较：①完整套件数量最多；②数量相同时按 `(priority, kit_id)` 升序排列的交付0/1向量取字典序最大；③所有已分配槽位的 `成品长度-min_mm` 之和最小；④已选套按 `(priority, kit_id)`、槽位按 `slot_id` 排列的实物引用序列字典序最小（引用按前三个字符串及整数 `unit` 逐字段比较，不把整数转成字符串）。不允许逐套贪心后宣称最优。允许最终配成0套。

预览无预留、无出库副作用。输出含工作区身份、完整规范化请求及其哈希、依据的成品修订版 `base_finished_revision`、选中套及逐槽实物/根/长度、未选套 `unselected_kit_ids`（仅表示在最终全局方案中未选中，不表示该套单独不可配）、排除件及原因、剩余可用候选，以及足以独立核对四层比较的指标（`kits_selected`、`kit_order` 与 `selection_vector`、`excess_mm_total`、`piece_sequence` 等）。

提交 `delivery commit --workspace W --plan P --output O` 重新核对工作区身份、当前成品修订版、完整规范化请求与全局方案：手改配货、遗漏约束或非规范最优解均失败；任何版本过期都失败，即便计划配成0套。成功时在一个原子结果中冻结交付清单、登记 `dispatch_id`、占用所选全部成品并推进成品修订版；0套也登记一份有效交付结果并推进一次。此后任何请求都不能再次出库这些实物，解除质量事件也不能释放它们。两个同版预览至多一个先成功，其余须重新预览；与切割提交、事件变化并发时由提交锁串行化为单一先后次序，不会交出已被隔离或被另一单占用的件。交付不推进库存或成本修订版，不改动原切割票与成本明细，不使原切割计划仅因交付而过期。

同一 `dispatch_id` 携带完全相同的规范化请求与原计划重试，优先于版本检查返回原冻结结果，不重复占用；即使之后发生质量事件、切割或其他交付，也能补导出原结果。同 id 换请求、换方案或换来源版本均冲突（退出2），重新预览不能替换原交付。输出沿用原子新建：已有相同结果可重放，不同内容失败并保留旧文件；能预先确认的输出冲突在状态变更之前即被判定。保存中断不留下半套出库；状态已保存而导出失败后能用原计划恢复，不重复出库。成功退出0，输入、冲突或版本错误退出2。

状态查询 `delivery status --workspace W [--dispatch D]`：无 `--dispatch` 时列出全部真实成品的当前归属、`available`/`isolated`/`delivered` 状态与活动事件——已交付与质量覆盖是两个维度，被召回的实物保持 `delivered` 且显示其活动事件，不会回到待配池。带 `--dispatch` 时返回原冻结清单，并另列当前受影响套件：任一槽位根被活动事件覆盖则该整套 `recall=true`，列出该套根上的全部活动事件及实际受影响实物；同套其他根的件不会被伪称为质量受影响件。未知交付身份报错（退出2）。

召回定位 `delivery affected --workspace W --incident I`：对已知的活动或已解除事件，按其根原材与真实交付事实列出全部历史交付、套件与真实实物引用，并显示该事件是否仍活动；未知事件报错（退出2）。事件可能在出库后才登记，也可能先登记、解除后才允许出库，定位均按根与真实交付事实计算，不依赖事件登记时的冻结报告。既有事件报告、交付文件与关账查询保持不变，当前影响另行呈现。

# 局部检验与回收切割 v1

局部检验把已经定位、允许剔除的节疤记录为某库存条目自身坐标下的半开区间，回收切割再把区间之外的干净料道加工成订单件，把多段干净余料纳入同一库存、成本与交付链。检验与回收都是库存工作区之上的新命令；单批 `cut-ticket`、无局部检验的普通批次、质量事件、成本关账与交付的既有契约保持不变，旧 `state.json` 缺少检验字段时按“无局部缺陷”就地升级。

## 局部检验

`inspection register --workspace W --source S --output O` 的输入：非空 `inspection_id`、非空 `entry_id`、非负严格整数 `expected_inventory_revision` 与 `reject_zones` 数组（最多32个原始区域，空数组合法，表示本次检验无局部缺陷）。每个区域含严格整数 `start_mm`、`end_mm`（布尔值不被当作整数），表示条目自身坐标下的半开区间，必须满足 `trim_head_mm <= start_mm < end_mm <= length_mm-trim_tail_mm`，否则退出2。区域允许重叠、相接与乱序；登记时取并集并把相接区间合并为规范区域。区域代表已包含剔除边界锯缝余量的完整不可用段，回收时不再在这些边界另扣锯缝。

任何尚未消耗的初始原材或余料都可被检验，包括正被整根质量事件隔离的条目；检验不解除隔离，活动事件仍同时优先于普通与回收工艺。未知条目、已消耗条目上的新登记、期待版本与当前库存修订版不一致均失败（退出2），不得追改历史票。

每次成功的新登记替换该条目当前采用的检验，并在同一次原子持久化中把库存修订版恰好推进一次——即使区域与上次相同或为空，因为它是一份新的工艺依据；它不推进成本或成品修订版，不改变已产成品、采购价或当前成本金额，仅检验或修订检验本身不产生成本损失。同一条目只有一份当前检验，新登记记录在历史日志中并标注 `replaced_inspection_id`。

幂等身份 `inspection_id`：相同 id 携带相同规范输入重试时优先返回原冻结回执，先于期待版本与条目存活性检查——即使库存版已过期或条目后来已消耗；规范输入保留期待版本，区域按合并后的并集比较（原始输入的顺序与切分仍显示在回执的 `raw_reject_zones`）。同 id 不同规范输入冲突。`inspection status --workspace W [--entry E]` 显示每次检验的原输入、规范区域、登记修订版、是否为当前采用，以及条目当前的 `current_reject_zones`、`requires_salvage`；条目没有记录时按无局部缺陷处理。检验登记使此前的普通计划与回收计划都按库存版过期。

## 回收计划与提交

普通 `plan` 只能使用当前没有非空剔除区的可用条目；带非空剔除区的条目必须走回收工艺，普通命令不得把区域当作不存在，也不得暗中压缩坐标。库存查询保持可用/消耗/整根隔离三个既有状态维度，同时在每个条目上显示 `reject_zones`、`requires_salvage` 与 `eligible_for_normal_plan`，避免把工艺不适用误称为已消耗。

`salvage plan --workspace W --source S --output O` 与 `salvage commit --workspace W --plan P --output O`。回收请求沿用批次的 `job_id`、`orders`、`kerf_mm`、`min_offcut_mm`，增加 `candidate_entry_ids`：1至4个互不重复的已知、尚未消耗且未被整根隔离的库存身份，否则退出2；只允许从这份清单选料，材种、长度与修边一律取真实库存事实，输入不能覆盖。每个候选的可加工范围是扣掉既有头尾修边后再扣掉当前剔除区得到的各个最大连续干净区间（料道）；无检验等同没有剔除区。候选合计最多8条非空料道，订单展开后最多12件，超限明确失败，不回退启发式；允许所有候选全被局部区域覆盖而配成0件。

一件订单必须完整放在一条同材料道内，不能跨越剔除区、拼接或重复加工。每条料道内已选订单件按 `(order_id, unit)` 升序，从料道左端连续加工、不留内部空隙；每件之后（含最后一件）扣本请求的 `kerf_mm`，锯缝不得伸出料道；未选订单为缺件，`unit` 为订单数量展开的正整数。料道切完后的末段长度为正且不小于 `min_offcut_mm` 才回收，否则为废料。某候选只要加工至少一件就一次消耗整个父条目：头尾修边、完整剔除区计损耗，各料道分别生成成品、锯缝与末段；该父条目上完全未加工的料道也按完整剩余段与同一阈值回收或报废。未加工任何件的候选保持原库存，不能仅为换身份或剔除而消耗。料道边界已含剔除余量，不再对每条料道套初始头尾修边。

固定工艺下求全局唯一方案，依次比较：①成品件数最大；②成品长度总和最大；③本次不可回收损耗毫米数最小（只计实际消耗父条目的头尾修边、剔除区、锯缝与低于阈值的料道末段，未使用库存不算损耗）；④所消耗父条目的完整长度总和最小；⑤规范放置序列字典序最小。规范放置序列按全部需求的 `(order_id, unit)` 排列，每件已配为 `(0, entry_id, start_mm)`，缺件为 `(1, "", 0)`，逐字段比较、数字保持整数。不允许逐料道贪心后宣称全局最优。候选、订单与检验区域输入数组重排不改变规范请求与方案。

预览无库存副作用，报告含工作区身份、完整规范请求及其校验身份、依据库存修订版、各候选采用的检验身份、料道（含根坐标）、逐件坐标、缺件、消耗父条目、未使用候选、全部新增余料、四层目标指标与规范放置序列。每张父条目的票以 `partitions` 完整划分其整个物理长度：所有正长度段按坐标排列、不重叠、不遗漏，区分 `trim_head`/`trim_tail`、`defect_reject`、`piece`、`kerf`、可回收 `offcut` 与报废 `offcut`，并同时给出局部坐标与对应根原材坐标。

每段可回收余料有工作区内唯一稳定身份 `offcut/<job_id>/<父条目>#<序号>`，可区分同父同批的多个余料；旧单尾料身份 `offcut/<job_id>/<父条目>` 保持可查。余料记录父条目、来源工单、根、父内起止坐标，自身从0开始计长、修边为0，初始没有局部区域，可直接供普通 `plan` 使用，也能接受后续检验。旧库存没有显式根坐标时，沿原切割票的余料起点逐代恢复偏移，不把多代余料的局部坐标直接当根坐标。

`salvage commit` 使用现有库存版与提交锁串行化语义，重新核验规范请求、检验依据、完整物理划分与唯一最优结果，拒绝篡改、跨工作区或过期计划。它与普通提交共用 `job_id` 身份空间，同一 id 不能分别成功扣两次料。一次新回收提交原子完成父条目消耗、全部余料入库与原切割票格式可识别的真实成品登记，库存修订版与成品修订版各推进一次，成本版不变；0件结果也登记有效工单并各推进一次，但不消耗库存。同 id 同原计划重试优先返回原冻结结果；同 id 换请求、工艺、来源版或方案冲突。普通/回收竞争提交同版至多一个先成功；检验、质量事件与切割竞争由同一把提交锁排成一致先后关系。状态已保存而导出失败后，用原计划可补出相同结果，不重复生成任何分支。

## 与成本、关账、交付和召回的衔接

回收票按其完整物理划分逐段整数分币，沿用最大余数、物理起点决胜口径；同一父票的所有料道连同修边、剔除区一起分摊一次，禁止先把父成本分给料道再二次取整。剔除段使用明确损耗类别 `defect_reject`；每段可回收余料分别携带自己的整数分币进入后代，不得把多个余料成本合为一个余额，也不得重算成根成本直接摊最终成品。价格更正沿新旧混合来源链传递，旧票原分摊保持兼容，仅检验或修订检验不产生成本损失——真正剔除发生在回收切割提交时。关账桥接继续正确分开历史价差与生产转移，历史库存截点能还原各分支的存在与消耗，旧关账保持冻结。

回收产生的成品以原四元引用 `(job_id, entry_id, order_id, unit)` 进入 `delivery`；多条料道同根仍可满足同根配纹。质量事件登记后的召回沿根覆盖全部新旧分支，`status --job` 可查询回收提交。登记与提交均沿用输出原子新建：已存在同结果允许重放，内容不同失败且保留旧文件；可预判的输出冲突在状态变更前判定；保存中断不留下部分余料或部分成本事实。成功退出0，输入、版本或身份冲突退出2。

# 客户退回成品的返料再制造与价值接续 v1

客户把仍保持原切割长度的完整成品实物退回仓库。退回是实物收货事实，不是退货申请，也不是撤销交付：不处理客户截短、拼接、替换或退款。登记把整件一次性转为可再加工的返料库存，原交付占用、收货与召回凭据永久保留。

## 退回登记与身份

`return register --workspace W --source S --output O` 的输入：非空字符串 `return_id`、非负严格整数 `expected_inventory_revision` 与 `expected_finished_revision`（布尔值不得冒充整数）、1至32项的 `items` 数组（数组类型或规模错误即失败）。每项含非空 `dispatch_id`、`kit_id`、`slot_id` 与 `piece`；`piece` 使用既有四元引用对象 `{job_id, entry_id, order_id, unit}`，前三项非空，`unit` 为正严格整数。同一请求不得重复列槽位 `(dispatch_id, kit_id, slot_id)`，也不得重复列同一实物引用，否则退出2。

只接收本工作区已成功交付的该套该槽：冻结槽位中的实物引用必须与 `piece` 完全相等（四字段按类型严格比较）。真实但未交付的成品、未选中的套、空交付、错交付/套/槽、计划中的件、余料和未知引用都不能登记；同一实物引用在整个工作区最多成功退回一次，换 `return_id` 或换交付声明都不能再次退回。允许只退回原套中的部分槽位，也允许一张回单包含多个交付的件；任一项无效，整张回单不生效，状态与已有回单完全不变。

规范请求保留两个期待版本及全部上述字段；`items` 按四元引用的三个字符串、整数件号，再按交付/套/槽排序，输入数组重排不改变身份。相同 `return_id`、相同规范请求的重试优先返回原冻结回执——即使两个期待版本已经过时、原件已经再加工或根后来被隔离；同 id 不同输入冲突（退出2）并保留旧回执。对新回单，两个期待版本必须分别等于当前库存修订版与成品修订版，过期时明确失败，不悄悄更换依据。

## 一次性从成品转为返料

一次新登记在同一把提交锁、同一次原子状态写入中完成全部项目的退回占用、返料创建与回执冻结；多项回单也只把库存修订版与成品修订版各推进一次，成本修订版不变，重放不推进。其他操作不能看到只入库部分项目或只转走部分成品的中间状态。登记前生成的普通/回收切割预览按库存版过期，交付预览按成品版过期，即使其最终方案没有使用这些件；价格更正不使任何切割或交付预览过期。

每个项目创建一个工作区内唯一稳定、`kind` 可识别为 `return` 的新库存身份 `return/<return_id>/<序号>`，序号在回单内从1起。身份由结构化内容指纹参与区分，任意合法字符串（含分隔符）构成的不同来源不会因简单拼接而碰撞。返料保留精确的回单、原交付/套/槽、原成品四元引用、原成品来源库存、根原材与材种；其长度只能取原切割坐标之差，返料自身从0计长、头尾修边为0；不新增采购原材或采购价，也不继承来源条目上与成品之外位置有关的局部剔除区。返料根坐标起点等于原成品来源条目的根偏移加该切件的局部起点；来源可以是初始原材、普通多代余料、回收多分支余料或更早的返料，局部坐标永远不被当作根坐标。

原成品四元身份永久保留原交付占用，不能重新加入 `delivery` 的候选池；旧交付重放仍返回原清单，不删除原槽、不换成新件。当前交付查询在原状态维度之外，明确列出该件的 `returned_by`、对应返料身份与归还事实；按交付查询保留原冻结结果，另列哪些槽已退回。返料只有通过真实新切割形成新四元成品身份后才能再次交付；新成品后来也可以按它自己的真实交付再次退回，但这绝不允许祖先成品再次退回。

物理收货不能因根正在质量隔离而丢失：活动根事件下仍可登记退回，新返料及其后代沿同一根受全部活动事件约束，普通与回收工艺都不得使用它；解除部分覆盖事件仍不可加工，解除最后一个事件后才可使用尚未消耗的返料，且不能复活已加工身份。没有根隔离或局部剔除区的返料真正参加现有普通 `plan/commit`；之后可用既有 `inspection` 检验它，有非空剔除区时普通工艺不得使用，必须走现有 `salvage`，后者产生的各分支继续进入原库存、成品与交付流程。不为返料另设绕过原版本或质量判断的切割功能。

登记不依赖原材是否已经登记价格；回执只冻结实物事实与操作版本（登记前后两个修订版、逐项目的原实物、真实尺寸与根坐标、新库存身份与来源），不冻结将来成本计算采用的金额。`return status --workspace W [--return R]` 列出回单；指定回单时返回原冻结回执，并单列每个返料当前可用/已消耗、消耗工单、活动事件与当前检验信息，不用当前状态改写回执。根事件的历史交付定位同时保留原交付与再制造后的新交付；退回不抹去召回历史，也不把同套其他根的件说成受该根事件影响；既有事件报告保持冻结。

## 成本不能在成品和返料两处存在

退回是价值转移，不是采购、损耗、负采购价或新收入。在一个库存截点、该次选定根价下，原成品此前按真实父票分得的完整整数分值原封不动成为返料输入成本：不重新按根长比例估价，不因归还再取整。返料再切时，才按现有最大余数、物理起点决胜规则对本票全部物理分段分摊一次；局部回收仍把同父所有料道连同修边、剔除区一次分摊。后代再次退回时沿同样的真实来源接续，不能跳过前代票的整数分摊，也不能在回单里缓存首次退回时的金额来应付后来改价。

当前和新关账的 `detail.pieces` 保留曾产生成品的四元行身份：截至该截点已退回的原件，其当前 `amount_cents` 为0，并指出转入的返料（`returned_by`、`return_entry_id`）；未退回者保留该次价格投影下的成品分值。原生产票 `tickets` 中该段的原分摊仍作为加工依据显示，不为让汇总相等而把票内分摊改为0。明细另列退回价值转移 `value_transfers`，含回单、操作库存版、来源四元引用、目标库存身份及该价格投影下的整数金额；它是可核对的转移依据，不作为额外资产计入汇总。返料未消耗时只在 `inventory` 计价，消耗后只由新成品、损耗和未消耗余料承接。每根在任意截点仍满足：当前保有成品价值＋累计加工损耗＋未消耗库存价值＝采用的根采购成本；历史切割票、历史交付中重复出现的祖先实体不能再算一次资产。原材缺价时，退回仍可收货，但成本查询及关账仍按原契约失败并列出缺价根。

库存截点不仅筛选切割，还必须准确包含已在该截点之前发生的退回转换：退回前，该原件仍持有成品价值，返料尚不存在；退回后且再切前，原件转为0、返料持有价值；再切后，返料不再计为存量。不能用当前 `returned_by`、当前库存 `status` 或全部回单无条件倒灌历史截点。质量事件和局部检验本身依旧不转移金额。

价格更正穿过“库存→成品→返料→新切割”以及普通/回收混合来源，重新遵守每一票和每次无损转移的分币口径；原关账文件与查询结果保持冻结。连续关账继续先在上轮库存截点按本轮价格重算历史价差，再在同一本轮价格下比较新旧库存截点得到生产转移；退回造成的成品减少与返料增加归既有 `production_cents`，不是历史价差。各行按原身份并集补0，返料行在不属于该截点时不提前出现。每行和各级汇总仍满足 期初＋历史价差＋生产转移＝期末，每根生产转移合计为0。

## 输出与退出码

登记沿用输出原子新建语义：已有相同回执可重放，内容不同失败且保留旧文件；能预先确定的输出冲突在任何状态变更之前判定。保存失败不能留下部分项目、重复返料或转走了成本却没有物料；状态已保存而导出失败后，用原请求可补出同一回执，不重复入库。成功退出0；输入、身份、版本与输出冲突退出2。旧工作区的 `state.json` 缺少退回字段时按“从未发生退回”就地升级，无需人工改文件；未发生退回的原场景、单批 `cut-ticket`、既有工单与已冻结交付、检验、事件及关账结果保持原契约。
